Elections — Deployment Runbook

Production deployment on DigitalOcean. Three phases: stand up a small test droplet, scale up for the event, scale back down after.

Contents
  1. Prerequisites
  2. Phase 1 — Small test droplet (~$18/mo, 20 users)
  3. Phase 2 — Scale up for the event (~$84/mo, 500 users)
  4. Phase 3 — Return to small after the event ($18/mo)
  5. Monitoring during the event
  6. Troubleshooting

Prerequisites

Before you start Phase 1, have these ready:

  • Code on GitHub — the droplet pulls from a git remote
  • DigitalOcean account with payment method on file and SSH public key uploaded
  • Free domain from DuckDNS (e.g. yourname.duckdns.org) — needed for HTTPS
  • Values for .env: generate a strong DB password with openssl rand -base64 24, decide your APP_TIMEZONE, admin credentials
Make your GitHub repo private — the SQL dumps contain personal voter data (names, mobile numbers, addresses).

Phase 1 Small test droplet — 20 users

Goal: full production stack on a cheap droplet (~$18/mo) for the 20-user trial. ~60 minutes total.

1.2 Install system packages

During apt upgrade you may see SSH/network config prompts. Always pick "keep the local version currently installed" for sshd — otherwise you can lock yourself out. 
apt update && apt upgrade -y

# PHP 8.2 PPA + all needed extensions + system services
apt install -y software-properties-common
add-apt-repository -y ppa:ondrej/php
apt update
apt install -y nginx mysql-server redis-server \
  php8.2-cli php8.2-fpm php8.2-mysql php8.2-redis \
  php8.2-xml php8.2-mbstring php8.2-curl php8.2-zip \
  php8.2-gd php8.2-bcmath php8.2-intl php8.2-sockets \
  unzip git ufw

# Composer (don't apt install composer — it's outdated)
cd /tmp && curl -sS https://getcomposer.org/installer -o composer-setup.php
php composer-setup.php && mv composer.phar /usr/local/bin/composer
chmod +x /usr/local/bin/composer && rm composer-setup.php

1.3 MySQL setup

# Generate a strong password and save it in your password manager
DB_PASS=$(openssl rand -base64 24)
echo "DB password: $DB_PASS"

# Create DB + app user (replace YOUR_DB_PASS with the value above)
sudo mysql < /etc/mysql/mysql.conf.d/elections.cnf <<'EOF'
[mysqld]
max_connections          = 50
wait_timeout             = 600
innodb_buffer_pool_size  = 512M
innodb_buffer_pool_instances = 1
innodb_log_file_size     = 128M
innodb_flush_log_at_trx_commit = 1
innodb_flush_method      = O_DIRECT
innodb_file_per_table    = 1
innodb_lock_wait_timeout = 30
table_open_cache         = 2000
open_files_limit         = 65535
max_allowed_packet       = 64M
character-set-server     = utf8mb4
collation-server         = utf8mb4_unicode_ci
sql_mode                 = "NO_ENGINE_SUBSTITUTION"
slow_query_log           = 1
slow_query_log_file      = /var/log/mysql/slow.log
long_query_time          = 1
EOF
systemctl restart mysql

1.4 Deploy the app

mkdir -p /var/www && cd /var/www
git clone https://github.com/YOUR_USER/elections.git
cd elections

composer install --no-dev --optimize-autoloader

# Copy the production env template
cp .env.production .env
nano .env   # fill in DB_PASSWORD, APP_TIMEZONE, SUPERADMIN_USER, SUPERADMIN_PASS, etc.
Never put trailing # comments on the same line as a value in .env. PHP dotenv handles them inconsistently for base64-padded values like APP_KEY. Clean them with: 
sed -i 's/[[:space:]]\+#[[:space:]].*$//' /var/www/elections/.env
# Generate APP_KEY, prepare storage dirs
php artisan key:generate --force
mkdir -p public/uploads public/profile_picture storage/framework/{cache,sessions,views} storage/logs bootstrap/cache
php artisan storage:link

# Load DB schema (use sudo mysql — dump has DEFINER clauses needing SUPER)
sudo mysql election < /var/www/elections/final.sql

# Apply the unique-vote constraint migration
php artisan migrate --path=database/migrations/2026_05_23_211212_add_unique_vote_per_user_round.php --force

# Make www-data own the whole project (simpler for test droplet)
chown -R www-data:www-data /var/www/elections
chmod -R g+rwX /var/www/elections

1.5 Install Octane and bring it up under systemd

# Make the rr binary executable (it's a Linux binary already)
cd /var/www/elections && chmod +x rr

# Install Octane components (publishes config; answer "no" to "install RR via composer?")
sudo -u www-data php artisan octane:install --server=roadrunner

# Create the systemd service
cat > /etc/systemd/system/elections-octane.service <<'EOF'
[Unit]
Description=Elections Octane Server (RoadRunner)
After=network.target mysql.service redis-server.service
Requires=mysql.service redis-server.service

[Service]
Type=simple
User=www-data
Group=www-data
WorkingDirectory=/var/www/elections
ExecStart=/usr/bin/php /var/www/elections/artisan octane:start --server=roadrunner --host=0.0.0.0 --port=8000 --workers=6 --max-requests=1000
ExecReload=/usr/bin/php /var/www/elections/artisan octane:reload
Restart=on-failure
RestartSec=5
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable elections-octane
systemctl start elections-octane
systemctl status elections-octane --no-pager | head -15

1.6 Nginx + HTTPS

Sign up at DuckDNS, create a subdomain pointing to the droplet's IP.

# Remove the default Nginx site
rm -f /etc/nginx/sites-enabled/default

# Write our site config (replace YOURNAME with your DuckDNS subdomain)
cat > /etc/nginx/sites-available/elections <<'EOF'
server {
    listen 80;
    server_name YOURNAME.duckdns.org;
    client_max_body_size 64M;

    access_log /var/log/nginx/elections-access.log;
    error_log  /var/log/nginx/elections-error.log;

    location /css/      { root /var/www/elections/public; expires 7d; }
    location /js/       { root /var/www/elections/public; expires 7d; }
    location /images/   { root /var/www/elections/public; expires 7d; }
    location /fonts/    { root /var/www/elections/public; expires 30d; }
    location /uploads/  { root /var/www/elections/public; }
    location /profile_picture/ { root /var/www/elections/public; }
    location /storage/  { root /var/www/elections/public; }
    location /favicon.ico { root /var/www/elections/public; log_not_found off; }

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }
}
EOF
ln -sf /etc/nginx/sites-available/elections /etc/nginx/sites-enabled/elections
nginx -t && systemctl reload nginx

# Open firewall (HTTPS-Only mode in browsers will fail without this)
ufw allow OpenSSH
ufw allow 'Nginx Full'
ufw --force enable

# Get a TLS certificate
apt install -y certbot python3-certbot-nginx
certbot --nginx -d YOURNAME.duckdns.org --non-interactive --agree-tos \
  --email YOU@example.com --redirect

1.7 Final config — point Laravel at the new HTTPS URL

# Update .env
sed -i 's|APP_URL=.*|APP_URL=https://YOURNAME.duckdns.org|' /var/www/elections/.env
sed -i 's/SESSION_SECURE_COOKIE=false/SESSION_SECURE_COOKIE=true/' /var/www/elections/.env

# Cache config + reload Octane
cd /var/www/elections
sudo -u www-data php artisan config:cache
sudo -u www-data php artisan view:cache
systemctl reload elections-octane

# Verify
curl -sI https://YOURNAME.duckdns.org/
Open in browser: https://YOURNAME.duckdns.org/ — you should see the login page with logo and styling. Log in with your SUPERADMIN_USER / SUPERADMIN_PASS.

1.8 Snapshot the working droplet

  1. DO panel → your droplet → Power Off
  2. Once status shows OFF, Snapshots → Take Snapshot → name it elections-phase1-working
  3. After ~2 min, Power On

Snapshot cost: ~$0.12/month — your free rollback point.

Phase 2 Scale up for the event — 500 users

~24 hours before the event. ~$84/mo while large. ~15 minutes total.

2.1 Snapshot first (in case anything goes wrong)

  1. Power off the droplet
  2. Take a snapshot named elections-pre-event
  3. Keep the droplet OFF for the resize step

2.2 Resize the droplet

1DO panel → droplet → Resize
Pick "CPU and RAM only" (faster, reversible, keeps the disk and IP)
Choose General Purpose → g-4vcpu-16gb (4 vCPU / 16 GB) — ~$84/mo
2Click Resize · wait ~3 min · then Power On
The IP, TLS certificate, domain, code, database, and DuckDNS DNS all stay the same. Only the box gets bigger.

2.3 Re-tune for the bigger machine

SSH in and run these three blocks — bump workers, buffer pool, max connections:

# 1. Octane workers: 6 → 16
sed -i 's/--workers=6/--workers=16/' /etc/systemd/system/elections-octane.service
systemctl daemon-reload

# 2. MySQL buffer pool 512M → 4G, connections 50 → 200
sed -i 's/innodb_buffer_pool_size  = 512M/innodb_buffer_pool_size  = 4G/' /etc/mysql/mysql.conf.d/elections.cnf
sed -i 's/max_connections          = 50/max_connections          = 200/' /etc/mysql/mysql.conf.d/elections.cnf

# 3. Restart both services
systemctl restart mysql
systemctl restart elections-octane

# Verify
ps aux | grep octane:worker | wc -l                # expect ~16
mysql -uroot -e "SHOW VARIABLES LIKE 'max_connections';"
curl -sI https://YOURNAME.duckdns.org/

2.4 Pre-event sanity checklist

  • ☐ HTTPS still loads, padlock shows green
  • ☐ Login as superadmin works
  • ☐ Test vote from a voter account writes to vote_master
  • ☐ systemctl status for nginx, mysql, redis-server, elections-octane all active (running)
  • ☐ df -h / shows >10 GB free
  • ☐ ufw status shows only SSH + Nginx Full open

Troubleshooting (lessons from the first deploy)

"No application encryption key has been specified" — even after key:generate
  1. An earlier export APP_KEY=... in your shell might be persisting through sudo as an empty string. Open a fresh SSH session.
  2. Check for trailing # comment on the APP_KEY line in .env — they break the parser for base64-padded values:
    sed -i 's/[[:space:]]\+#[[:space:]].*$//' /var/www/elections/.env
  3. Rebuild config cache: sudo -u www-data php artisan config:cache
  4. Verify the key is baked in: sudo -u www-data php -r "echo (include '/var/www/elections/bootstrap/cache/config.php')['app']['key'] ?: 'EMPTY';"
Port 8000/8001 already in use after restart

pkill -f 'artisan serve' sometimes doesn't match. Use the port instead:

fuser -k 8000/tcp
sleep 2
ss -ltnp | grep ':8000' || echo "Port free"
Browser shows ERR_CONNECTION_RESET / NS_ERROR_NET_TIMEOUT on static assets

Chrome and Safari auto-upgrade http:// subresources to https://. Without a TLS cert, those requests fail silently. Fix: get a TLS cert (see Phase 1 step 1.6). DuckDNS + Let's Encrypt is free.

Login fails with "المقترع غير موجود" (Voter not found)

The login controller uses env('SUPERADMIN_USER') directly. With config:cache on (the production default), env() returns null in controllers. Make sure the values are exposed via config:

# In config/app.php, add:
'default_user'     => env('APP_DEFAULTUSER'),
'superadmin_user'  => env('SUPERADMIN_USER'),
'superadmin_pass'  => env('SUPERADMIN_PASS'),

# Then in loginController.php (and any view), replace
# env('SUPERADMIN_USER') with config('app.superadmin_user'), etc.
Octane workers crash with "sync_worker_receive_frame: Network: EOF"

You're running with a custom .rr.yaml referencing the non-existent octane:worker command. Don't use a custom .rr.yaml; let Octane manage RoadRunner:

sudo -u www-data php artisan octane:start --server=roadrunner --workers=6
SQL dump fails with "Access denied; you need SUPER privilege"

The dump contains DEFINER=root@... clauses on views/triggers. Load it as the MySQL root user via socket auth:

sudo mysql election < /var/www/elections/final.sql

The app itself still connects as elections_app for normal queries.

I edited .env and the site stopped working

Laravel reads from bootstrap/cache/config.php, not .env, when config is cached. After ANY .env change:

cd /var/www/elections
sudo -u www-data php artisan config:cache
systemctl reload elections-octane
